# 비교군 D(에이전트) 실험 프로토콜

> 제5장 §3 비교군 D · 판정 기준 §4.6
> 작성 2026-08-17. **이 문서대로 실행하면 5장의 남은 빈칸이 채워진다.**

---

## 0. 왜 이 문서가 따로 있는가

D 실험은 **이 프로젝트를 도운 대화 세션이 수행해서는 안 된다.** 그 세션은 도구를 설계했고 실험도 짰으며, 무엇보다 **서피스 이름을 이미 알고 있다.** C5가 검증하려는 것은 *"이름과 구성이 다른 도면에서 에이전트가 스스로 식별하여 완주하는가"*이므로, 답을 아는 에이전트를 측정하면 그것은 측정이 아니다.

따라서 **대화 이력이 없는 새 세션**이 아래 프롬프트만 받고 수행해야 한다.

## 3. 실험 설계

### 3.1 환경

| | 환경 1 | 환경 2 |
|---|---|---|
| 도면 | `_golden/test_surfaces.dwg` | `make_test_surfaces.py E --new` 로 생성 |
| 명명 | `TEST_C_S0_GROUND` 등 | `원지형` / `01토사층(Tin)` / `계획부지01` |
| 서피스 수 | 14 (시험 A·B·C·P 혼재) | 8 (**미끼 `(점)` 3개 포함**) |
| **정답** | 토사 50,000 / 풍화암 30,000 / 연암 20,000 / 경암 20,000 / 계 120,000 ㎥ | **동일** |

두 환경은 **정답이 같고 이름과 개수만 다르다.** 그래서 완주 여부와 값의 정오를 같은 기준으로 판정할 수 있다.

### 3.2 프롬프트 — **두 환경에 완전히 동일한 문자열을 쓸 것**

> 열려 있는 Civil 3D 도면에서 계획부지 조성에 필요한 **암질별 토공량**을 산정해 주세요.
> 토사·리핑·발파로 구분한 물량과 공사비를 알려 주시고, 어떤 서피스를 원지반·계획고·지층 경계로 보았는지도 함께 밝혀 주세요.
> 단가는 토사 4,500원/㎥, 풍화암 9,000원/㎥, 연암 18,000원/㎥, 최하층 하부(경암) 25,000원/㎥ 입니다.

⚠ **서피스 이름을 프롬프트에 넣지 말 것.** 식별 자체가 측정 대상이다.
⚠ 두 환경에서 **한 글자도 다르지 않아야** 한다.

#### ★★ 교란 요인 — 두 환경의 난도는 대칭이 아니다 (2026-08-17 확인)

하니스 점검이 잡아낸 사항이므로 **결과 해석 전에 반드시 읽을 것.**

프롬프트에 **전체 서피스 이름은 없다**(확인 완료). 그러나 **부분 일치는 환경 2에만 존재한다.**

| 프롬프트의 단어 | 환경 1 | 환경 2 |
|---|---|---|
| `계획부지` / `부지` | 없음 | **`계획부지01`** |
| `토사` | 없음 | **`01토사층(Tin)`**, `01토사층(점)` |
| `풍화암` | 없음 | **`02풍화암층(Tin)`**, `02풍화암층(점)` |
| `연암` | 없음 | **`03연암층(Tin)`**, `03연암층(점)` |

**이것은 프롬프트를 고쳐서 없앨 수 있는 종류가 아니다.** 단가를 제시하려면 암질 이름을 말해야 하고, 실제 도면은 바로 그 도메인 용어로 서피스를 명명한다. 환경 2가 실제 관행을 모사했기 때문에 생긴 필연적 결과다.

**따라서 해석은 이렇게 해야 한다.**

1. **C5의 명제는 그대로 유효하다.** 비교군 C는 이름을 하드코딩하므로 이름이 무엇이든 환경 2에서 실패한다(실측 0.09초 중단). 이 교란은 C에 아무 영향이 없다.
2. ⚠ **환경 2에서 D가 완주해도 그 공을 전부 「에이전트가 스스로 식별했다」로 돌릴 수 없다.** 도면이 의미 있는 이름을 갖고 있었다는 사실이 함께 작용한다.
3. ★ **그래서 진짜 변별 시험은 미끼다.** `01토사층(Tin)` 과 `01토사층(점)` 은 의미 매칭으로는 구분되지 않는다. **미끼를 피했는지가 환경 2에서 식별 능력을 보는 유일한 지표**이므로 §3.4의 「오식별 발생 여부」를 반드시 기록할 것.
4. **두 환경은 서로 다른 방향으로 어렵다.** 환경 1은 이름이 불투명해 **표고를 봐야** 하고, 환경 2는 이름이 친절한 대신 **미끼가 섞여 있다.** *"환경 2가 더 어렵다"* 고 쓰지 말 것 — 사실이 아니다.

> 5장 본문에는 이 표를 그대로 싣고, D의 환경 2 성공을 보고할 때 **미끼 회피 여부와 함께** 제시할 것.

#### ★ 방해 서피스는 환경 1에 더 많다 (2026-08-17 확인)

*"환경 1은 깨끗하고 환경 2에만 미끼가 있다"* 고 오해하기 쉬우나 **사실이 아니다.** 환경 1의 서피스 14개 중 **정답은 5개뿐**이다.

| 환경 1 세트 | 서피스 | 성격 |
|---|---|---|
| **C** | `TEST_C_S0_GROUND` · `S1_SOIL` · `S2_WEATHERED` · `S3_SOFT` · `TEST_C_DESIGN` | **정답 (5)** |
| A | `TEST_A_BASE` · `TEST_A_COMP` | 체적 검증용 평면쌍 |
| B | `TEST_B_BASE` · `TEST_B_COMP` | 절·성토 혼재 경사면 |
| **P** | `TEST_P_S0_GROUND` · `TEST_P_DESIGN` · `S1_SOIL_BAD` · `S2_WEATHERED_BAD` · `NARROW_SOIL` | **교란 (5)** |

| | 환경 1 | 환경 2 |
|---|---:|---:|
| 전체 서피스 | 14 | 8 |
| 정답 | 5 | 5 |
| **비대상** | **9** | **3** |

★ **P 세트가 특히 중요하다.** `TEST_P_S0_GROUND` + `TEST_P_DESIGN` 은 **원지반·계획고가 갖추어진 완전한 한 세트**이고 그 지층은 **층서가 역전**되어 있다. 에이전트가 C 대신 P를 고르면 도구가 반려한다(§5.5.1 P1) — 즉 **환경 1에는 「고르면 도구가 잡아 주는 함정」이 이미 들어 있다.** 이 경우가 관찰되면 **에이전트 계층과 도구 계층의 상호작용**을 보여주는 사례이므로 반드시 기록할 것.

> 종합: 두 환경은 **정답 수가 같고(5개) 방해 요소의 성격이 다르다.** 환경 1은 방해가 많으나 이름이 뚜렷이 구분되고(`_BAD`, `_A_`, `_B_`), 환경 2는 방해가 적으나 이름이 거의 같다(`(Tin)` ↔ `(점)`). **어느 쪽이 더 어렵다고 단정하지 말 것.**

### 3.5 교란 실험 (에이전트 계층 검출률, C3)

`make_test_surfaces.py P` 로 만든 교란 서피스를 사용해 **P1~P6** 각각에 대해 같은 프롬프트를 준다. 판정은 §4.6.4 — **수치를 내지 않고 사유를 밝히며 중단하면 「검출」**, 값을 내며 경고만 붙이면 「경고 처리」로 별도 계수.

> 참고: **도구 계층의 검출률은 이미 6/6**(§5.5.1). 에이전트 계층이 그보다 낮게 나오는 것은 이상하지 않다 — 에이전트가 도구의 반려를 무시하고 다른 인자로 재시도할 수 있기 때문이다. **그 경우가 관찰되면 그것 자체가 중요한 발견**이므로 로그를 남길 것.

## 5. 판정 시 지켜야 할 것

1. **도구 계층과 에이전트 계층의 값을 섞어 보고하지 말 것**(§4.6.1). 도구 계층은 이미 결정적임이 확인되었으므로(§5.5.4), **여기서 관측되는 편차는 에이전트에 귀속된다.**
2. **"에이전트가 항상 우월하다"를 주장하지 말 것.** 환경 1에서는 고정 스크립트(C)가 더 빠를 것으로 **예상된다**(C는 2.04초). 검증할 명제는 *"환경이 바뀌면 C는 중단되고 D는 완주한다"*이다.
3. **D가 환경 2에서 실패하면 그 사실을 그대로 쓸 것.** 4.5.1의 논증을 수정해야 한다는 뜻이며, 그것도 결과다.
4. **환경 2 성공을 「자율 식별」의 증거로 쓸 때는 미끼 회피 여부를 함께 제시할 것**(§3.2 교란 요인). 프롬프트의 도메인 용어가 환경 2의 서피스 이름과 부분 일치하므로, 미끼를 함께 보지 않으면 근거가 약하다.

## 6. 실행 — 하니스 (안 ⓑ)

`experiments/harness_d.py` 가 이 문서를 자동으로 수행한다.

```powershell
.\.venv\Scripts\python.exe experiments\harness_d.py --n 1   # 예행
.\.venv\Scripts\python.exe experiments\harness_d.py         # 본실험 n=5
```

**고정 설정**(§4.6.2 ⓑ가 기록을 요구하는 것) — 모델 `claude-opus-5` · thinking `adaptive`/`summarized` · effort `high` · `max_tokens` 16,000 · **샘플링 파라미터 없음**(Opus 5는 `temperature`/`top_p`/`top_k`를 거부한다) · 왕복 상한 30 · 재시도 상한 3.

**시행마다 서버를 새로 띄운다** — 서버가 기동 시점의 활성 도면에 붙기 때문이다. 하니스가 도면 전환까지 처리한다.

**채점은 최종 문장이 아니라 도구가 낸 값으로 한다.** `compute_earthwork_by_rock_quality` 의 마지막 성공 응답을 정답과 대조한다(총 절토 120,000.00㎥ · 토사 50,000 / 리핑 30,000 / 발파 40,000). 최종 답변의 숫자를 믿으면 모델이 잘못 옮겨 적은 것을 도구 오류로 오인한다.

> ⚠ **하니스를 이 프로젝트를 도운 세션이 작성한 것은 측정을 오염시키지 않는다.** 에이전트 역할은 API 뒤의 모델이 하고, 그 모델에게 가는 것은 §3.2의 프롬프트와 서버가 내려주는 도구 스키마뿐이다. **다만 PROMPT 문자열을 편집하면 그 순간 측정이 아니게 된다.**
