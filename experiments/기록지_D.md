## 5. ⚠ 이 방식의 한계 — 5장에 그대로 쓸 것

| 항목 | 상태 |
|---|---|
| 모델 버전 | ⚠ **기록 불가** — Claude Desktop 이 노출하지 않는다 |
| 샘플링 파라미터 | ⚠ **기록 불가·고정 불가** |
| 워크플로 전체 시간 | 스톱워치 수동 측정 (정밀도 제한) |
| 도구 호출 수·재시도 | 답변 화면에서 손으로 세야 한다 |

§4.6.2 ⓑ 는 재현성 측정의 전제로 *"모델 버전·샘플링 파라미터를 고정하고 기록할 것"* 을 요구하는데, 이 방식으로는 충족할 수 없다.

> **5장에는 이렇게 쓴다.**
> 워크플로 계층의 측정은 상용 호스트에서 수동으로 수행하였으므로, 모델 버전과 샘플링 파라미터를 고정·기록하지 못하였다. 따라서 본 절의 워크플로 재현성 수치는 **그 조건이 통제되지 않은 상태의 관측값**이며, 도구 계층의 결정성(§5.5.4)과 같은 수준의 엄밀성을 갖지 않는다.

⚠ **이 한계를 감추지 말 것.** 밝히면 *"제약 하에서 정직하게 보고했다"* 가 되고, 감추면 심사에서 *"무엇을 고정한 측정이냐"* 에 답할 수 없다.

> ★ **대안이 있다는 사실도 함께 적어 둔다.** `harness_d.py` 는 API 로 같은 실험을 수행하며 **모델·thinking·effort·max_tokens·샘플링을 결과에 기록**하고 도구 호출 순서·시간을 자동으로 남긴다. 비용 때문에 채택하지 않았을 뿐 방법이 없어서가 아니며, 이는 6.4 향후 연구에 쓸 수 있다.
