## 0. 매 시행 준비 — 명령 하나

```powershell
cd C:\Users\bim\source\civil3d-mcp
.\.venv\Scripts\python.exe experiments\activate_env.py 3     # 1 · 2 · 3
```

이 한 명령이 **도면 열기 → 활성화 → 서피스 확인 출력 → 표식 서피스 심기 → 점검표 출력**을 전부 한다. 시행이 끝나면:

```powershell
.\.venv\Scripts\python.exe experiments\activate_env.py clean
```

### ⚠ 시행 전 점검 셋 — 하나라도 어긋나면 그 시행은 무효다 (§4.6.6)

| # | 조건 | 왜 |
|---|---|---|
| 1 | **새 대화**에서 수행 | 같은 대화에서 두 번째를 돌리면 앞 시행의 답을 보고 하는 것이다 |
| 2 | 그 대화에 **Civil 3D 도구만** 붙어 있다 | ★ 파일·터미널 접근이 되면 **이 PC 의 정답표(이 파일)를 읽을 수 있다.** 첫 시행을 폐기한 이유가 정확히 이것이다 |
| 3 | 답변이 **표식 서피스**를 언급하는지 사후 확인 | 답변 텍스트만으로는 도구를 썼는지 알 수 없다 |

> ★ **조건 2 의 실질적 통제 수단은 「Desktop 에 파일 도구를 붙이지 않는 것」이다.** 정답표를 다른 파일로 옮기는 것은 보조 수단일 뿐이며, 파일 접근이 열려 있으면 어디에 두어도 읽힌다.

### 그 밖 수칙

- 붙여넣기 **직전에 스톱워치 시작**, 최종 답변이 끝나면 정지
- 프롬프트를 **손으로 고치지 말 것** — 한 글자만 달라도 환경 간 비교가 깨진다
- **되물어도 답해 주지 말 것.** 답을 주고 이어가면 「개입 완주」로 **따로** 센다(§4.6.3)
- 시행 중 **Civil 3D 를 건드리지 말 것** — 서버가 활성 도면을 추종한다
- Claude Desktop **재시작은 불필요**하다 (도면만 바꾸면 된다)

## 5. ⚠ 이 방식의 한계 — 5장에 그대로 쓸 것

| 항목 | 상태 |
|---|---|
| 모델 버전 | ⚠ **기록 불가** — Claude Desktop 이 노출하지 않는다 |
| 샘플링 파라미터 | ⚠ **기록 불가·고정 불가** |
| 워크플로 전체 시간 | 스톱워치 수동 측정 (정밀도 제한) |
| 도구 호출 수·재시도 | 답변 화면에서 손으로 세야 한다 |

§4.6.2 ⓑ 는 재현성 측정의 전제로 *"모델 버전·샘플링 파라미터를 고정하고 기록할 것"* 을 요구하는데, 이 방식으로는 충족할 수 없다.

> **5장에는 이렇게 쓴다.**
> 워크플로 계층의 측정은 상용 호스트에서 수동으로 수행하였으므로, 모델 버전과 샘플링 파라미터를 고정·기록하지 못하였다. 따라서 본 절의 워크플로 재현성 수치는 **그 조건이 통제되지 않은 상태의 관측값**이며, 도구 계층의 결정성(§5.5.4)과 같은 수준의 엄밀성을 갖지 않는다.

⚠ **이 한계를 감추지 말 것.** 밝히면 *"제약 하에서 정직하게 보고했다"* 가 되고, 감추면 심사에서 *"무엇을 고정한 측정이냐"* 에 답할 수 없다.

> ★ **대안이 있다는 사실도 함께 적어 둔다.** `harness_d.py` 는 API 로 같은 실험을 수행하며 **모델·thinking·effort·max_tokens·샘플링을 결과에 기록**하고 도구 호출 순서·시간을 자동으로 남긴다. 비용 때문에 채택하지 않았을 뿐 방법이 없어서가 아니며, 이는 6.4 향후 연구에 쓸 수 있다.
