# 수리종단 기준값 생성 절차 — `2-2. 동수경사도 작성.dyn` 재실행

> **목적** — 제5장 5.2.1의 마지막 ☐ 를 닫는다. 기준 산출물 「BIM 기반 사업부지 검토 요약 보고서」의 **「관로 수리계산」 시트에 수두 값이 남아 있지 않아** `compute_hydraulic_profile` 을 실무 산출물과 대조할 수 없다. 원 워크플로의 그 단계를 다시 돌려 기준값을 만드는 것이 이 절차다.
>
> **작성 2026-08-19.** 실행 전에 `.dyn` 을 판독해 세운 절차이며, **아직 한 번도 돌려 보지 않았다.** 아래에서 「확인한 것」과 「예상」을 구분해 표기한다.
>
> ⚠ **이 문서의 예측값을 논문 본문에 옮기지 말 것.** 실행 결과가 나오기 전까지 그것은 계산이지 측정이 아니다. 「미수행을 수치로 채우지 않는다」는 제5장의 규약이 그대로 적용된다.

## 0. 먼저 알아 둘 것 — 이 시트는 「실행되지 않은」 것이 아니다

판독으로 확인한 사실이다.

- 「관로 수리계산」 시트의 **표제행 15개**는 `2-2` 의 스크립트 노드 안에 **축자로 박혀 있는 문자열과 한 글자도 다르지 않다.**
- 그 노드가 유일하게 소수 셋째 자리에서 반올림하는 항목이 관로연장인데, 실제로 그 칸만 `1708.293` 으로 세 자리이고 측점 세 개는 반올림 없이 남아 있다.

즉 **그래프는 실행되어 그 시트를 썼고, 열 칸이 빈 값으로 기록되었다.** 따라서 이번 재실행의 성격은 *"안 해 본 것을 해 보는 것"*이 아니라 **"왜 열 칸이 비었는지를 밝히고 채우는 것"**이다.

### 유력한 원인 — 입력 양식의 셀 서식 (상관은 확인, 인과는 추정)

`주요 설계 매개변수_수리종단검토.xlsx` 를 셀 타입까지 읽으면 이렇다.

| 항목 | 값 | 셀 타입 |
|---|---|---|
| 설계 관경 | 250 | **숫자** |
| 설계 유량 | '10000' | ⚠ **문자열** |
| 시점수두 | `=B4+B5` (= 113) | 수식 · 비고 「(입력x)」 |
| 위치수두 | '93' | ⚠ **문자열** |
| 펌프양정(시점) | '20' | ⚠ **문자열** |
| 잔류수두 | 10 | 숫자 |
| 펌프양정(가압지점) | 13 | 숫자 |

그리고 「관로 수리계산」 시트에서 **살아남은 입력은 관경 하나뿐**이고, **비어 있는 열 칸은 전부 위 문자열 셋에서 내려오는 값들**이다. 유량에서 유속·동수경사가, 위치수두와 펌프양정의 합인 시점수두에서 손실수두·종점수두·잔류수두가 나온다.

**숫자형 1건은 성공하고 문자열형 3건은 실패했다 — 상관이 완전하다.** 다만 문자열이 산술 노드에서 실제로 어떻게 처리되는지는 돌려 보아야 확정된다.

> ★ 그래서 이 절차는 **1차(원본 그대로) → 2차(사본에서 셀을 숫자로)** 두 번 돌린다. 두 결과가 다르면 **그 차이 자체가 논문 재료**다 — 입력 양식의 셀 서식이 산출을 좌우한다는 것은 제6장 6.3 아홉째(조건 미통제)의 강한 실물이 된다.

## 3. 도면을 열고 전제를 확인한다

`_수리종단_재실행\01.관로노선검토 준비.dwg` 를 연다. **완료본(`02.…완료.dwg`)이 아니다** — 완료본에는 이미 만들어진 종단이 있어 트레이스가 그것을 잡는다.

`2-2` 는 도면에 대해 다음을 **전제**한다. *확인함 — 그래프의 노드 연결을 따라간 결과다.*

| 전제 | 왜 중요한가 |
|---|---|
| 선형(Alignment)이 하나 이상 있을 것 | 그래프는 **모든 선형 중 첫 번째**(`list[0]`)를 잡는다. 둘 이상이면 어느 것이 잡힐지 순서에 달려 있다 |
| 그 선형에 종단(Profile)이 하나 이상 있을 것 | 역시 **첫 번째**를 원지형 종단으로 쓴다 |
| 종단 스타일 **`Design Profile`** 이 도면에 있을 것 | 이름을 문자열로 찾는다. 없으면 종단 생성이 실패한다 |
| 레이블 세트 **`_NO Labels`** 가 있을 것 | 〃 |
| 레이어 **`C-ROAD-PROF`** | 〃 (없으면 자동 생성될 수 있으나 확인 대상) |

**확인 방법** — 도구공간(TOOLSPACE) → 탐색기 탭에서 선형 개수와 이름, 그 아래 종단 개수를 적어 둔다. 설정 탭에서 종단 스타일 목록에 `Design Profile`, 레이블 세트에 `_NO Labels` 가 있는지 본다.

**기록해 둘 것** — 선형 개수 · 첫 선형의 이름 · 연장 · 종단 개수 · 첫 종단의 PVI 개수. 나중에 결과를 해석할 때 쓴다.

> 관로연장이 **1,708.293 m** 근처로 나오면 원 실행과 같은 선형을 잡은 것이다. 크게 다르면 `list[0]` 이 다른 선형을 잡은 것이므로 **그대로 진행하지 말고 멈출 것.**

**방법** — 종단뷰를 클릭 → 우클릭 → 종단뷰 특성 → 표고 탭 → 「사용자 높이」로 바꾸고 위 값 입력.

## 6. 결과 판정

사본의 요약 보고서를 열어 **「관로 수리계산」 시트 2행**을 본다.

### 성공 — 15칸이 모두 찬 경우

예상값과 대조한다(§7). **A2 셀의 정렬을 반드시 확인할 것** — 왼쪽 정렬이면 유량이 숫자가 아니라 텍스트로 쓰인 것이고, 그러면 대표 화면의 수식이 깨질 수 있다.

### 실패 — 어느 칸이 비었는지로 원인을 가른다

| 빈 칸의 모양 | 원인 | 다음 조치 |
|---|---|---|
| **15칸 전부** 빔 | 종단이 만들어지지 않았다 — 스타일·레이블세트·레이어 이름이 도면에 없거나 선형/종단이 없다 | §3 으로 돌아가 스타일 존재 확인 |
| **C·D·J·L·N 다섯 칸만** 차고 수두 열 칸이 빔 | **원 실행과 똑같은 결과.** 매개변수의 문자열 셀이 원인일 가능성이 크다 | §8 의 2차 실행으로 |
| **E·F·H·I 네 칸만** 빔 | 스크립트 노드가 값을 묶어 내보내는 방식이 이 Dynamo 버전에서 다르게 해석된 것 | 그 노드의 출력을 Watch 로 확인 |

> ★ **도면 유래 세 칸(J·L·N)이 나오는지가 두 실패를 가르는 열쇠다.** 나오면 도면은 정상이고 매개변수가 문제, 안 나오면 도면·스타일이 문제다.

## 7. 예상값 — ⚠ 계산이지 측정이 아니다

관경 250 ㎜ · 유량 10,000 ㎥/일 · 연장 1,708.29259150895 m · 시점수두 113 m 로 그래프의 산식을 그대로 계산한 값이다. **실행 결과와 대조하는 용도이며, 이 표를 논문에 옮기지 말 것.**

| 항목 | 예상값 |
|---|---:|
| 유속 | 2.36 m/s |
| 동수경사 | 33.69 ‰ |
| 시점수두 | 113 m (= 위치수두 93 + 펌프양정 20) |
| 손실수두 | 57.55 m |
| 종점수두 | 55.45 m |

*(적용 유속계수 C = 100. `2-2` 의 분기는 `D ≤ 700 → 100`이며, 같은 데이터셋의 `2-1` 은 `D < 800 → 100` 으로 경계가 다르다. D250 에서는 둘 다 100 이므로 이번 계산에는 영향이 없다.)*

> ⚠ **유속 2.36 m/s 는 적정 범위(0.3~3.0 m/s) 안이지만 상한에 가깝다.** 이것은 도구의 판정 대상이지 이 절차의 성공 조건이 아니다.

## 8. 2차 실행 — 셀 서식 가설의 시험

1차에서 **수두 열 칸이 비었다면** 다음을 한다. 이때 **사본의 매개변수 파일만** 고친다.

1. `_수리종단_재실행\주요 설계 매개변수_수리종단검토.xlsx` 를 연다
2. **B2(설계 유량) · B4(위치수두) · B5(펌프양정)** 세 칸을 지우고 **숫자로 다시 입력**한다 (`10000` · `93` · `20`)
3. 셀 서식이 「텍스트」로 되어 있으면 「일반」으로 바꾼 뒤 다시 입력한다 — 서식만 바꾸면 값은 문자열로 남는다
4. 저장하고 §5 를 다시 실행한다

**두 실행의 결과를 모두 기록할 것.** 1차 실패 · 2차 성공이면 원인이 확정되고, 그 사실은 논문의 다음 두 곳에 쓰인다.

- **제5장 5.2.1** — 「상관은 확인, 인과는 추정」으로 적어 둔 문단을 **인과 확정**으로 올린다
- **제6장 6.3 아홉째** — 입력 양식만으로는 제3자가 재현할 수 없다는 한계에, **셀 서식이 산출을 좌우한다**는 항목을 더한다

## 9. 성공한 뒤 — 무엇을 대조하는가

기준값이 생기면 본 연구의 `compute_hydraulic_profile` 을 같은 입력으로 호출해 대조한다.

계산 함수의 이름은 **`hydraulic_profile`** 이다(`compute_hydraulic_profile` 은 MCP 에 노출되는 도구 이름이고 그 안에서 이 함수를 부른다). 시그니처는 실조회로 확인하였다.

```python
hydraulic_profile(
    flow_m3_s,            # 10000/86400
    diameter_mm,          # 250
    start_elevation_m,    # 93.0   ← 위치수두
    start_pump_head_m,    # 20.0   ← 시점 펌프양정
    ground_profile,       # [{"station_m": .., "elevation_m": ..}, ...]  ← 도면 종단
    min_residual_head_m,  # 10.0
    pump_head_m=0.0,      # 13.0   ← 가압지점 펌프양정
    station_interval_m=None, c_value=None, site_id=None,
)
```

⚠ **시점수두 113 m 를 그대로 넣지 말 것.** 이 함수는 위치수두와 시점 펌프양정을 **따로** 받아 안에서 더한다. 113 을 `start_elevation_m` 에 넣고 양정을 또 주면 20 m 가 두 번 더해진다.

⚠ `ground_profile` 은 도면에서 뽑아야 한다. 그 추출까지 포함한 대조 절차는 결과가 나온 뒤에 확정한다 — **지금 미리 적으면 실행해 보지 않은 절차를 적는 것이 된다.**
